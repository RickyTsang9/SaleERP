# 销售管理系统功能实施计划书

## 一、建设目标

在现有销售、采购、库存、财务、经营看板和系统管理能力基础上，继续把系统从“业务数据录入系统”升级为“流程协同、风险预警、经营分析一体化系统”。建设过程遵循现有 RuoYi 分层架构，后端保持 controller -> service -> mapper 的调用链路，前端沿用现有业务页面、API 封装和菜单加载方式。

## 二、实施原则

1. 优先复用现有业务表、权限、接口和页面，不重复建设已有能力。
2. 每期功能先完成可使用闭环，再逐步增强自动化、分析和移动化能力。
3. 后端 SQL 保持小写，新增查询集中在 service 和 mapper 层。
4. 前端页面保持现有 Element Plus 与业务页面风格，先保证效率和清晰度。
5. 不改动与当前功能无关的业务逻辑，降低影响范围。

## 三、分阶段实施计划

### 第一阶段：统一待办中心

目标：将分散在销售、采购、仓库、财务、预算和经营决议中的待处理事项集中展示。

实施内容：

1. 新增待办汇总接口，统计待审核销售单、待财务审核销售单、待审核采购单、待审核入库单、待审核出库单、库存预警、逾期应收、近期应付、待审批年度预算、未完成经营决议事项。
2. 新增前端“待办中心”页面，支持按待办类型、优先级、关键词筛选。
3. 待办项提供“去处理”入口，跳转到原业务页面并带上筛选参数。
4. 新增菜单 SQL，方便部署库补充菜单和权限。

验收标准：

1. 用户可以在一个页面看到主要待处理事项。
2. 点击待办项能进入对应业务页面。
3. 后端编译通过，前端生产构建通过。

### 第二阶段：销售与采购全链路追踪

目标：打通订单从创建、审核、出入库、应收应付、收付款到退货的完整链路。

实施内容：

1. 销售订单详情增加链路视图：订单、状态历史、出库、应收、回款、退货。
2. 采购订单详情增加链路视图：采购、入库、应付、付款、退货。
3. 单据时间轴展示操作人、操作时间、状态变化和审核意见。

### 第三阶段：客户与商品经营画像

目标：让销售和管理层能从客户、商品两个维度判断经营质量。

实施内容：

1. 客户详情增加累计销售、累计回款、未收金额、回款率、最近下单、最近跟进、主要购买商品和风险等级。
2. 商品分析增加销量排行、销售额排行、毛利排行、退货率排行、库存周转和滞销提醒。
3. 客户跟进提醒按销售员、下次跟进时间和沉睡客户生成待办。

### 第四阶段：库存与仓库作业增强

目标：提升仓库作业效率和库存准确性。

实施内容：

1. 增加扫码出入库和扫码盘点能力。
2. 完善批次管理和效期管理。
3. 将库存上下限预警规则做成可维护配置。

### 第五阶段：财务与经营分析升级

目标：强化资金风险管理和管理层报表能力。

实施内容：

1. 增加客户对账单、供应商对账单、应收账龄、应付账龄明细。
2. 增加收付款计划和到期提醒。
3. 经营日报、周报、月报自动生成，经营简报支持导出。

## 四、推荐实施顺序

1. 统一待办中心。
2. 销售订单全链路追踪。
3. 采购订单全链路追踪。
4. 客户经营画像。
5. 商品销售和库存周转分析。
6. 应收账龄和客户对账单。
7. 库存预警规则配置。
8. 扫码出入库和扫码盘点。
9. 经营日报、周报、月报。
10. 批次和效期管理。

## 五、第一期开发范围

本次先实施“统一待办中心”，以只读汇总和快速跳转为主，不直接在待办中心修改业务单据状态。审批、审核、收付款和库存处理仍回到原业务页面完成，确保第一期风险可控。
